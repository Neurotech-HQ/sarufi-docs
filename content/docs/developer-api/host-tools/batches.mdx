The agent sends host tool calls in **batches**. The widget runs a batch for you; over the [Chat API](./api-reference#host-tools-over-the-chat-api) your server runs it. Either way the rules are the same.

## The batch

```json
{
  "step": 1,
  "mode": "sequential",
  "calls": [
    {
      "call_id": "htc_01K8...",
      "name": "create_order",
      "args": { "product_id": "kitenge_blue", "quantity": 2 },
      "parameters": { "type": "object", "properties": { "product_id": { "type": "string" }, "quantity": { "type": "integer" } } },
      "timeout_ms": 15000,
      "order": 1
    }
  ]
}
```

| Field | Notes |
|---|---|
| `step` | 1 for the first batch of a user's turn, then 2, 3 and so on. |
| `mode` | `parallel` when every call may overlap, `sequential` when any call in the batch belongs to a tool marked `concurrency: "serial"`. |
| `calls[].call_id` | Unguessable and single-use. Answer each call with it. |
| `calls[].name`, `args` | The tool and the arguments the model chose. |
| `calls[].parameters` | The tool's JSON Schema, so you can check `args` before running anything. |
| `calls[].timeout_ms` | How long the call may take. |
| `calls[].order` | 1-based position in the batch. |

## Modes

- **`parallel`**: run every call at once and answer each as soon as it is ready.
- **`sequential`**: run the calls in `order`. On the first failure, stop, and answer every remaining call with `skipped`. The agent is told those calls were not attempted because an earlier one failed.

Mark tools that write or have side effects (`create_order`, `pay`) with `concurrency: "serial"` in their definition, so they never overlap.

A call that needs an earlier result never shares a batch with it: it comes in a **later step**, after the agent has seen the first results.

## Results

Each call is answered with one result:

```json
{ "call_id": "htc_01K8...", "ok": true, "result": { "order_id": "ord_9", "total": 60000, "currency": "TZS" } }
```

```json
{ "call_id": "htc_01K8...", "ok": false, "error": "failed", "message": "The order could not be created." }
```

| `error` | When |
|---|---|
| `not_available` | The tool cannot run here: no handler, or turned off on this page. |
| `invalid_args` | The args do not match the tool's schema. |
| `timeout` | The call ran past `timeout_ms`. |
| `failed` | The handler failed. `message`, up to 300 characters, says why. |
| `skipped` | Not attempted, because an earlier call in a sequential batch failed. Send no `message`. |

`result` is any JSON value up to 32 KB once serialized. Return only what the agent needs.

Answer every call in the batch. A call left unanswered expires after its timeout and the agent sees it as failed. An expired or answered call is never sent again; a batch replayed after a reconnect contains only calls still waiting.

## Example: create an order, then pay

```javascript
ChatWidget.registerTools({
  create_order: async ({ product_id, quantity }, { signal }) => {
    const r = await fetch("/api/orders", {
      method: "POST", signal, credentials: "include",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ product_id, quantity }),
    });
    if (!r.ok) throw new Error("The order could not be created.");
    const order = await r.json();
    return { order_id: order.id, total: order.total, currency: order.currency };
  },
  pay: async ({ order_id }, { signal }) => {
    const r = await fetch(`/api/orders/${order_id}/pay`, { method: "POST", signal, credentials: "include" });
    if (!r.ok) throw new Error("Payment did not go through.");
    return { status: (await r.json()).status };
  },
});
```

With both tools defined `concurrency: "serial"`, the visitor says "buy two of the blue kitenge and pay with my wallet":

1. **Step 1** (`sequential`): `create_order({ product_id, quantity: 2 })` returns `{ order_id: "ord_9", total: 60000 }`.
2. **Step 2** (`sequential`): with the order id now known, the agent calls `pay({ order_id: "ord_9" })`.
3. The agent confirms the payment to the visitor.

If `create_order` fails, there is no step 2: the agent tells the visitor and does not try to pay.
