## Tool definition

```json
{
  "name": "get_balance",
  "description": "The signed-in user's current wallet balance.",
  "parameters": { "type": "object", "properties": {} },
  "timeout_ms": 15000,
  "concurrency": "parallel",
  "requires_verified_user": true
}
```

| Field | Type | Required | Notes |
|---|---|---|---|
| `name` | string | yes | `^[a-z][a-z0-9_]{1,47}$`. Unique across a bot's linked sets, and not the name of a built-in or MCP tool |
| `description` | string | yes | Up to 1024 characters. What the model reads to decide when to call it |
| `parameters` | object | yes | An object JSON Schema, at most 8 KB, integers only |
| `timeout_ms` | integer | no | Default 30000, from 1000 to 300000 |
| `concurrency` | string | no | `parallel` (default) or `serial` for writes and side effects. See [Steps and Modes](./batches) |
| `requires_verified_user` | boolean | no | `true` offers the tool only to a verified user. Default `false` |

## Tool sets

Owner-registered tools live in **tool sets** at the workspace level, and are **linked** to chatbots, the same way knowledge bases and MCP servers are. A bot offers only the tools of the sets linked to it.

### Create or Update a Set

```http
PUT /api/dev/v1/workspaces/{workspace_id}/host-tools/{set_id}
Authorization: Bearer <api-key>
Content-Type: application/json
```

You choose `set_id`: 3 to 64 lowercase letters, digits or dashes, starting with a letter or digit. A `PUT` replaces the whole set.

| Field | Type | Required | Notes |
|---|---|---|---|
| `name` | string | yes | Display name, up to 80 characters |
| `tools` | array | yes | [Tool definitions](#tool-definition) |

```bash
curl -X PUT https://developers.sarufi.io/api/dev/v1/workspaces/<workspace-id>/host-tools/wallet \
  -H "Authorization: Bearer <your-api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Wallet",
    "tools": [
      {
        "name": "get_balance",
        "description": "The signed-in user'\''s current wallet balance.",
        "parameters": { "type": "object", "properties": {} },
        "timeout_ms": 15000,
        "requires_verified_user": true
      },
      {
        "name": "list_transactions",
        "description": "The user'\''s most recent transactions, newest first.",
        "parameters": {
          "type": "object",
          "properties": {
            "limit": { "type": "integer", "minimum": 1, "maximum": 50 },
            "direction": { "enum": ["in", "out"] }
          }
        },
        "timeout_ms": 15000,
        "requires_verified_user": true
      }
    ]
  }'
```

**Response - 200 OK**

```json
{
  "set_id": "wallet",
  "name": "Wallet",
  "tools": [ { "name": "get_balance", "...": "..." }, { "name": "list_transactions", "...": "..." } ],
  "linked_chatbots": ["01KBOT..."],
  "updated_at": "2026-10-28T09:00:00.000Z"
}
```

### Get a Set

```http
GET /api/dev/v1/workspaces/{workspace_id}/host-tools/{set_id}
Authorization: Bearer <api-key>
```

Returns the same body. `404` when the set does not exist.

### Link Sets to a Chatbot

```http
PUT /api/dev/v1/chatbots/{chatbot_id}/host-tools/links
Authorization: Bearer <api-key>
Content-Type: application/json
```

```json
{ "set_ids": ["wallet", "site-search"] }
```

Replaces the chatbot's links. Send `[]` to unlink everything. Up to 16 sets.

**Response - 200 OK**

```json
{ "chatbot_id": "01KBOT...", "set_ids": ["wallet", "site-search"] }
```

| Status | When |
|---|---|
| `404` | A set is not one of this workspace's |
| `409` | Two linked sets define the same tool name, or a name clashes with a built-in or MCP tool. The message names the clash |
| `422` | More than 16 sets, or a malformed body |

## Host tools over the Chat API

Your server can run host tools for a [Chat API](../chat) session. The API is server-to-server with your key, so the session counts as a verified user, and no host token or origin is involved.

### Send a message with tools

`POST /api/dev/v1/chatbots/{chatbot_id}/chat/sessions/{session_id}/messages` accepts two more fields:

| Field | Type | Required | Notes |
|---|---|---|---|
| `tools` | array | no | Up to 16 [tool definitions](#tool-definition) your server runs for this session, kept for the session |
| `active_tools` | string[] | no | The tool names you can run now. It only narrows what is offered, and replaces the previous list |

```bash
curl -X POST https://developers.sarufi.io/api/dev/v1/chatbots/<chatbot-id>/chat/sessions/<session-id>/messages \
  -H "Authorization: Bearer <your-api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "message": "What is my balance?",
    "tools": [
      {
        "name": "get_balance",
        "description": "The user'\''s current wallet balance.",
        "parameters": { "type": "object", "properties": {} }
      }
    ]
  }'
```

The response gains `status`, and a `tools` batch when your server has work to do:

| Field | Type | Notes |
|---|---|---|
| `status` | string | `complete` when the reply is finished, `tool_calls` when the agent is waiting for results |
| `tools` | object | Present with `tool_calls`: the [batch](./batches#the-batch) to run |

```json
{
  "session_id": "01K5M2Q8Z7C3V9R1T4Y6W0B2NE",
  "messages": [],
  "messages_count": 0,
  "current_state": "assistant",
  "timestamp": "2026-10-28T09:00:01+00:00",
  "status": "tool_calls",
  "tools": {
    "step": 1,
    "mode": "parallel",
    "calls": [
      { "call_id": "htc_01K8...", "name": "get_balance", "args": {}, "parameters": { "type": "object", "properties": {} }, "timeout_ms": 30000, "order": 1 }
    ]
  }
}
```

Show any `messages` that came with it, then run the calls.

### Post tool results

```http
POST /api/dev/v1/chatbots/{chatbot_id}/chat/sessions/{session_id}/tool_results
Authorization: Bearer <api-key>
Content-Type: application/json
```

| Field | Type | Required | Notes |
|---|---|---|---|
| `step` | integer | yes | The batch's `step` |
| `results` | array | yes | 1 to 32 [results](./batches#results), one per call |

```json
{
  "step": 1,
  "results": [
    { "call_id": "htc_01K8...", "ok": true, "result": { "amount": 125000, "currency": "TZS" } }
  ]
}
```

The response has the same shape as a message response: the agent's next `messages`, with `status: "complete"`, or another `tools` batch with the next `step`. Posting results continues the same message; it is not counted as a new one.

| Status | `detail` begins with | When |
|---|---|---|
| `404` | `unknown_call` | The results answer no call of this session |
| `409` | `step_mismatch` | The results answer a step that is not the one waiting |
| `409` | `expired` | The calls are no longer waiting, usually because they timed out |

### A full loop in Python

```python
import requests

BASE = "https://developers.sarufi.io/api/dev/v1"
HEADERS = {"Authorization": "Bearer <your-api-key>"}
CHATBOT_ID, SESSION_ID = "<chatbot-id>", "<session-id>"
URL = f"{BASE}/chatbots/{CHATBOT_ID}/chat/sessions/{SESSION_ID}"

TOOLS = [{"name": "get_balance", "description": "The user's current wallet balance.",
          "parameters": {"type": "object", "properties": {}}}]
HANDLERS = {"get_balance": lambda args: {"amount": 125000, "currency": "TZS"}}

def run(call):
    try:
        return {"call_id": call["call_id"], "ok": True, "result": HANDLERS[call["name"]](call["args"])}
    except KeyError:
        return {"call_id": call["call_id"], "ok": False, "error": "not_available"}
    except Exception:
        return {"call_id": call["call_id"], "ok": False, "error": "failed", "message": "Please try again later."}

def run_batch(batch):
    results = []
    for call in sorted(batch["calls"], key=lambda c: c["order"]):
        if batch["mode"] == "sequential" and results and not results[-1]["ok"]:
            results.append({"call_id": call["call_id"], "ok": False, "error": "skipped"})
            continue
        results.append(run(call))
    return results

reply = requests.post(f"{URL}/messages", headers=HEADERS,
                      json={"message": "What is my balance?", "tools": TOOLS}).json()
while True:
    for msg in reply["messages"]:
        print("Bot:", msg.get("text", msg["type"]))
    if reply["status"] != "tool_calls":
        break
    batch = reply["tools"]
    reply = requests.post(f"{URL}/tool_results", headers=HEADERS,
                          json={"step": batch["step"], "results": run_batch(batch)}).json()
```

The loop runs a sequential batch in order and marks the rest `skipped` after a failure. A real server would run a `parallel` batch concurrently.
